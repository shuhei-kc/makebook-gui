# makebook-gui

USIエンジン同士の連続対局で定跡を育てるブラウザーアプリです。対局の開始・待機・再開をブラウザーから操作でき、盤面・ツリー・棋譜・定跡DBを読み取り専用の観戦画面としてWeb公開できます。

定跡の更新処理は、たややんさんの [HiraganaSuisho / makebook2.py](https://github.com/tayayan/HiraganaSuisho/blob/main/makebook2.py) を基にしています。本家との違いは [docs/ALGORITHM.md](docs/ALGORITHM.md) にまとめています。

![観戦画面（実棋譜の固定データによる表示例）](docs/images/viewer.png?v=a470437f)

観戦画面では、盤面・横方向のツリー・対局タブ・課題一覧・連勝数を表示します。ツリーは局面の選択、矢印キーでの移動、ドラッグ、拡大縮小、現在局面への自動追従に対応しています。

## 必要なもの

- Python 3.12（依存パッケージは `cshogi` のみ）
- USIエンジンと評価関数（同梱していません）
- 動作確認済みの環境はWindowsです

## 起動

Windowsでは `Start.cmd` をダブルクリックします。初回は `.venv` を作って依存パッケージをインストールし、ブラウザーで操作画面を開きます。

コマンドで起動する場合：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
```

| オプション | 既定値 | 内容 |
| --- | --- | --- |
| `--data` | `data` | 設定と結果の保存先 |
| `--port` | `8765` | 操作画面のポート（このPCからのみ） |
| `--public-port` | `8766` | 観戦画面のポート（読み取り専用） |
| `--no-open` | — | 起動時にブラウザーを開かない |

例：`python app.py --data data-other --port 8775 --public-port 8776`

## 使い方

1. 操作画面の「設定・開始」を開きます（初回は自動で開きます）。
2. エンジンの実行ファイルと探索条件を指定します。
3. 必要なら「課題を追加」で課題局面を入力します。
4. 「開始・再開」を押します。

ブラウザーを閉じても対局は続きます。対局は操作画面とは別のプロセスで動くため、操作画面を起動し直すと、実行中の対局をそのまま表示・操作できます。

### 設定項目

| 項目 | 既定値 | 内容 |
| --- | --- | --- |
| 配信タイトル | 連続対局・定跡生成 | 観戦画面の見出し（120文字まで） |
| USIエンジンの実行ファイル | — | 相対パスはこのフォルダーが起点 |
| 共通起点 | `position startpos` | すべての対局の起点。通常は変更不要。[詳細](#共通起点の指定) |
| 1手の探索ノード数 | 20000000 | 定跡にない局面で `go nodes` に渡す値 |
| エンジンのスレッド数 | 4 | エンジン1つ当たりの `Threads` |
| Hash（MB／エンジン） | 1024 | エンジン1つ当たりの `USI_Hash` |
| 同時対局数 | 1 | 1〜8。使用スレッド数の目安は「スレッド数×同時対局数」 |
| 投了値 | 300 | `ResignValue` |
| 総手数上限 | 256 | 対局開始からではなく総手数で数えます（課題局面までの手数を含む） |
| 読み込み定跡DB | 空欄 | やねうら王形式の定跡DB（UTF-8）。[詳細](#読み込み定跡db) |
| 読み込み定跡を固定する側 | 固定しない | 選んだ側は、読み込みDBにある局面ではDBの手を指します |
| 引き分けの扱い | 先手負け | 循環・手数上限の対局で定跡をどう更新するか |
| 各課題の先手連勝数 | 100 | 課題を次へ進める条件 |
| 探索詳細を保存する | オフ | オンにするとUSI通信全文・PV・探索統計を保存 |

探索詳細を保存しない場合も、棋譜・定跡の更新・再開に必要な情報と、表示用の評価値は残ります。警告や障害の記録もオフのまま残します。

### ボタン

| ボタン | 動作 |
| --- | --- |
| 開始・再開 | 新しく開始するか、同じ設定の保存先を続きから再開します。待機中・エラー停止中の再開もこのボタンです |
| 現在局後に待機 | 進行中の対局が終わったら新しい対局を始めずに待ちます。プロセスは残ります |
| 現在局後に停止 | 進行中の対局が終わったら対局プロセスを終了します |

実行中は設定を変更できません。「現在局後に停止」で止めてから、新しい設定で開始してください。

### 共通起点の指定

共通起点は通常 `position startpos` のまま使い、検証したい局面は課題として追加します。共通起点を変えた場合、観戦画面の全体ツリーは次のように表示します。

- USI手順（`position startpos moves …`）：その最終局面までを全体ツリーに残し、以降の対局は課題別のツリーに表示します。
- 平手初期局面そのもの：全体ツリーは初期局面の1ノードになります。
- SFEN（`position sfen …`）：その局面を表示の起点とし、指定されていない過去の手順は作りません。

これは表示範囲の区切りで、対局や終了条件は変わりません。

### 読み込み定跡DB

- UTF-8のやねうら王形式に対応します。採用数を省略した4列の指し手行も読み込めます。
- 読み込んだ手の採用数は1から始まります。共通起点までの手順は、本家と同じく採用数1000で登録します。
- 読み込みは新規開始時の1回だけです。同じ保存先を再開するときに元のDBは必要ありません。
- 固定する側を選ぶと、DBのうちその側の手番の局面だけを固定定跡として使い、DBの手から一様にランダムで選びます。生成中の定跡よりも優先します。このとき読み込みDBは生成定跡の初期値にはしません（本家の「定跡の穴探索モード」と同じ）。

## 課題と連勝目標

課題は画面で追加・並べ替え・削除できます。課題局面は次のどちらかで入力します。

- 共通起点からの追加手順（例：`7g7f 3c3d`）
- 共通起点につながる `position` 形式の手順（例：`position startpos moves 7g7f 3c3d`）

課題は上から順に検証します。その課題での公式な先手勝ちが指定の連勝数に達すると次の課題へ進み、全課題を達成すると停止します。循環による打ち切りと手数上限は先手勝ちに数えず、連勝はリセットされます。

同時対局数が2以上でも、連勝が目標を超えて数えられないよう、進行中の対局の分だけ残りの勝ち数を予約します。前の課題の対局が残ったまま次の課題へ進むことはありません。

課題を指定しない場合は、共通起点から連続対局を続けます。

## 終局と定跡の更新

| 終局 | 公式結果 | 定跡の更新 | 先手の公式連勝 |
| --- | --- | --- | --- |
| 投了・詰み・入玉宣言 | 勝敗 | 勝敗に従う | 先手勝ちなら加算 |
| 循環（同一局面の2回目） | 未決着 | 「引き分けの扱い」に従う | リセット |
| 連続王手による循環（2回目） | 未決着 | 王手を続けた側の負け | リセット |
| 総手数上限 | 未決着 | 「引き分けの扱い」に従う | リセット |
| 中断・エラー | 未完了 | 更新しない | 変えない |

- 循環は本家と同じく、実際の対局開始局面以降で盤面・持駒・手番が初めて再一致した時点（2回目）で打ち切ります。通常の千日手のように4回は待ちません。
- 連続王手による循環は「引き分けの扱い」より優先して王手側の負けとして定跡を更新します。これは定跡生成のための扱いで、公式結果は未決着のまま、反則負けとは区別します。
- 入玉宣言は、エンジンの `win` を管理側で27点法の条件に照らして確認します。
- 旧版の4回設定で作成した保存先も、「開始・再開」以後の新しい対局には2回を適用します。保存済みの棋譜の条件や結果は書き換えません。

定跡の選び方と更新方法（負け側の手の削除、採用数の加算など）の詳細は [docs/ALGORITHM.md](docs/ALGORITHM.md) を参照してください。

## エンジンへ送る設定

自動で送るオプションは、画面で指定した `Threads`・`USI_Hash`・`ResignValue` の3つだけです。内蔵定跡（`BookFile`・`OwnBook`）、`EnteringKingRule`、評価関数、FV_SCALE、MultiPV、DrawValueなど、その他のオプションはエンジンの既定値のまま変更しません。

- エンジンが `Threads`・`ResignValue` を宣言しない場合は送信を省き、エンジン既定値で動かします。このとき保存先の `runtime/workers/*/usi.jsonl` に警告を残します。指定したスレッド数・投了値が効くかはエンジン側の対応を確認してください。
- `USI_Hash` はUSIの予約オプションなので、宣言を省略するエンジンにも送信します。
- 本家と同じく、探索時には現在局面のSFENだけを送り、手順は送りません。

## Web公開

| 画面 | URL | 公開 |
| --- | --- | --- |
| 操作画面 | `http://127.0.0.1:8765/` | しない |
| 観戦画面 | `http://127.0.0.1:8766/` | 可（読み取り専用） |

観戦画面のポート `8766` をリバースプロキシやトンネルにつなぎます。観戦画面からは設定・エンジンのパス・操作用トークンは見えず、操作もできません。操作画面のポート `8765` は公開しないでください。

Cloudflareの [Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) で一時的に公開する例：

```powershell
cloudflared tunnel --url http://127.0.0.1:8766
```

表示されたURLを共有できます。Quick Tunnelは一時公開用なので、固定URLで運用するときは通常のTunnelなどを設定してください。

公開例：[定跡生成配信 202610](https://478shogi.com/makebook/202610/)

## ダウンロードできるファイル

観戦画面と操作画面のボタンから保存できます。

| ファイル | 形式 | 内容 |
| --- | --- | --- |
| `sfens.txt` | SFEN | 全課題の完了棋譜 |
| `<課題ID>.sfen` | SFEN | 課題ごとの完了棋譜 |
| `book.db` | やねうら王DB | 現在の生成定跡 |

SFEN棋譜の末尾は、投了・詰みが `resign`、入玉宣言が `win`、循環の打ち切りが `rep_draw`、手数上限が `max_moves` です。定跡更新上の勝敗はJSON記録に残します。

## 保存データと再開

設定と結果は `data/` に保存されます。開始するたびに設定を比べ、同じなら前回の保存先を続きから再開し、違えば新しい保存先を作ります。以前の保存先も残ります。

```text
data/
  current.json              最後に開始した設定と保存先
  study-YYYYMMDD-HHMMSS-xxxxxx/
    campaign.json           この保存先の対局条件
    games.sfen              完了棋譜（追記）
    games.live.sfen         進行中の棋譜
    games.index.json        完了棋譜の索引
    launch.log              対局プロセスの起動ログ
    runtime/
      state.sqlite3         定跡・棋譜・課題進捗の正本
      manager.log           対局プロセスのログ
      workers/*/usi.jsonl   エンジンごとの警告・通信記録
      recovery/             復旧用のイベント記録とスナップショット
```

- 定跡・棋譜・課題進捗はSQLiteに1つのトランザクションでまとめて記録します。途中で強制終了しても、記録済みの結果は失われず、進行中だった対局は未完了として扱います。
- `games.sfen` は確定したバイト数とSHA-256を索引に記録します。追記の途中で終了した場合や旧形式の場合は、SQLiteから作り直します。
- 公開用のデータは記録の確定番号ごとに一度だけ作り、閲覧者の間で共有します。棋譜・ツリーは新しい対局だけを読み込みます。

## 開発者向け

```text
app.py        起動・操作画面・公開API
core/         USI通信・連続対局・定跡更新・保存
web/          操作画面・観戦画面
docs/         本家との比較、本家コード（upstream/）、画像
tests/        本家ロジックとの比較・模擬エンジンによる検証
```

テストは実際のエンジンを使わず、`tests/fake_engine.py` の模擬エンジンで実行します。

```powershell
.venv\Scripts\python -B -m unittest discover -s tests
```
