# makebook2との比較

比較元は [tayayan/HiraganaSuisho](https://github.com/tayayan/HiraganaSuisho) の `makebook2.py` と依存先の `Board.py`、コミット `8b215c174d0a9ce828a33f4978c52abf73dd625a`。元コード・MIT表記・SHA-256を `upstream/` に保存しています。

この文書では、本家（makebook2.py）に対してこのアプリを「公開版」と呼びます。使い方は [README](../README.md) を参照してください。

## 定跡の選択・更新

| 項目 | 本家と公開版の動作 | 確認箇所 |
| --- | --- | --- |
| 登録局面の指し手 | 候補から一様にランダム選択。採用数で重み付けしない | `core/runner.py` |
| 未登録局面 | 現在のSFENをUSIエンジンへ送り、指定ノード数で探索 | `core/runner.py` |
| 固定側 | 読み込みDBの固定側を共通定跡より優先する。固定側の着手も終局後の更新対象に含む | `app.py`、`core/runner.py` |
| 読み込みDB | 初期採用数を1にする | `app.initialize_book()` |
| 共通起点までの参考手順 | DBを読み込んだ後、各局面を「その1手・1000」に置き換える。実対局の更新対象へ混ぜない | `app.initialize_book()` |
| 終局後の更新 | 対局の手を末尾から遡る | `core/learning.py` |
| 負け側の削除 | 指した手を削り、同じ局面に別候補が残ったら逆順削除を止める | `legacy_learn()` |
| 削除を止めた後 | それより手前は負け側の手も含めて採用数を加算する | `legacy_learn()` |
| 採用数の加算 | 各出現について加算し、1局1回にまとめない | `legacy_learn()` |
| 並行対局 | 確定順に共通定跡へ反映。世代差を理由に古い対局の勝敗を拒否しない | `core/parallel.py`、`Candidates.learn_legacy()` |
| エンジン設定 | Threads・USI_Hash・ResignValueの3項目だけ。局ごとの `isready`・乱数seed固定なし | `app.campaign()`、`core/usi.py` |

本家の定跡更新ループをASTからそのまま抽出し、候補の残る削除・全削除・同一局面の再出現・固定手・古い世代を含む入力で比較しています。`Board.py` もそのまま読み込み、合法手順、駒取り・成り、盤面・持駒・手番の一致、最初の再到達を直接比較します。元の対話スクリプトや実エンジンはテストから起動しません。

## 循環・終了条件

本家の `Board.is_sennichite()` は、現在局面が過去に一度でもあれば真になります。公開版も盤面・持駒・手番が初めて再一致する**2回目**で止めます。通常の将棋の千日手成立まで4回待つ処理ではありません。

| 終了条件 | 公式結果 | 定跡更新 | 先手の公式連勝 |
| --- | --- | --- | --- |
| 投了・詰み・確認済みの入玉宣言 | 決着した勝敗 | 勝敗に従う | 先手勝ちだけ加算 |
| 通常の循環2回 | 未決着 | 引き分けの扱いに従う。既定は先手負け | リセット |
| 連続王手による循環2回 | 未決着 | 王手を続けた側の負け。引き分け設定より優先 | リセット |
| 総手数上限 | 未決着 | 引き分けの扱いに従う。既定は先手負け | リセット |
| 中断・エラー | 未決着・未完了 | 更新しない | 加算・リセットしない |

連続王手は、再一致した2局面の間で、その側のすべての着手が王手かを確認します。途中に王手でない着手があれば通常の循環です。2回での王手側負けは定跡生成のための扱いで、公式の連続王手の反則成立を主張するものではありません。保存理由は通常の `loop_abort` と `checking_loop_abort` を区別します。SFEN棋譜の終端は両方とも `rep_draw`、手数上限は `max_moves` です。更新上の勝敗はJSON記録に残します。

次は本家からの意図的な違いです。

- 循環履歴は実際の課題開始局面から数え、開始前の参考手順は除きます。本家の `Board.set()` は参考手順も履歴へ含めます。
- 再到達した局面では、次の指し手を選ぶ前に終了を判定します。本家は次の候補を一時バッファへ追加してから循環を判定します。公開版は未着手の次の手・投了などの終端文字列を定跡候補へ登録しません。
- 本家は連続王手を別扱いにしません。公開版では上記の王手側負けを追加しています。
- 手数上限と、公式結果・定跡更新上の結果の分離を追加しています。「更新しない」を選んだ通常循環・手数上限では候補の採用数や有効状態を変更しません。
- 非合法手・通信障害を検査し、入玉宣言は管理側で27点法の条件を確認します。エンジンの入玉規則オプションは変更しません。

旧版が4回設定で保存した棋譜は、その条件と結果を保持します。「開始・再開」時に通常の制御要求を記録し、以後の新しい対局を2回へ切り替えます。進行局の条件や過去の棋譜・定跡更新・連勝を遡って書き換えません。

## USI通信

本家と同じく現在SFENだけを送り、開始前や対局中の手順列は送りません。SFEN末尾の手数は、本家の固定値 `0` から、公開版では**実手数を維持**しています。盤面・持駒・手番が同じなら定跡キーは同じで、手数をキーへ含めません。

自動設定は画面指定の `Threads`・`USI_Hash`・`ResignValue` だけです。宣言されないThreads・ResignValueは警告を残して送信を省き、USI_Hashは予約オプションとして送ります。内蔵定跡OFFや評価関数・FV_SCALE・MultiPV・DrawValue等の変更は行いません。探索条件と並列数は設定可能です。

## 課題・保存・公開の追加

| 公開版の追加機能 | 条件・保存上の扱い | 検証 |
| --- | --- | --- |
| 順番付き課題・連勝目標 | 公式先手勝ちでのみ達成。進行局に残り勝ち数を予約し、前課題の局が残ったまま次へ進まない。全課題達成で停止 | `test_app.py` |
| SQLiteと復旧用スプール | 定跡・棋譜・課題進捗を一つのトランザクションで確定。ゲームIDで重複確定を防ぐ | `test_recovery_contract.py` |
| 保存済みの再開 | 同じ設定の保存先を継続。未完了局は完了局・勝敗・定跡更新へ加えない | `test_app.py`、`test_recovery_contract.py` |
| 探索詳細 | USI通信全文・PV・探索統計は既定オフ。棋譜・再開情報・表示用評価値は保持 | `test_app.py` |
| 全体・課題別ツリー | 全体は入力した課題までの経路、課題別は以後の完了局。SFEN指定から未知の過去手順を作らない | `test_projections.py` |
| 棋譜・定跡の出力 | `sfens.txt` は全完了局、定跡はやねうら王DB。UTF-8。Kiri等の独自出力なし | `test_app.py`、`test_projections.py` |
| 追記と公開キャッシュ | 完了棋譜は追記、進行局は別ファイル。公開用生成と操作ロックを分離 | `test_projections.py` |
| 操作と観戦の分離 | 操作側はHost・Origin・トークンを確認。観戦側は読み取り専用で設定やパスを公開しない | `test_app.py` |

`test_repetition.py` は先手・後手それぞれの連続王手、途中で王手が途切れる手順、開始前の循環、引き分け設定との優先関係を、模擬USIエンジンによる対局・定跡更新・SFEN出力・復旧時の再検証まで通して確認します。

この比較は処理と保存契約の検証です。並行実行の順序やエンジン探索の非決定性まで含め、同じ棋譜になることを保証するものではありません。
