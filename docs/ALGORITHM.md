# makebook2との比較

比較元は [tayayan/HiraganaSuisho](https://github.com/tayayan/HiraganaSuisho) の `makebook2.py`、コミット `8b215c174d0a9ce828a33f4978c52abf73dd625a`。元コードとMIT表記を `upstream/` に保存しています。

| 項目 | 公開版 |
| --- | --- |
| 登録局面の指し手 | 候補から一様にランダム選択。採用数で重み付けしない |
| 未登録局面 | 現在のSFENをUSIエンジンへ送り、指定ノード数で探索 |
| 終局後の更新 | 対局の手を末尾から遡って更新 |
| 負け側の削除 | 指した手を削り、同じ局面に別候補が残ったら逆順削除を止める |
| 削除を止めた後 | それより手前は、負け側の手も含めて採用数を加算。本家の `else` と同じ |
| 勝ち側の更新 | 各出現について加算。1局1回にまとめない |
| 並行対局 | 確定順に共通定跡へ反映。世代差を理由に古い対局の結果を拒否しない |
| 開始前の参考手順 | 1000で初期登録し、実対局の勝敗へ混ぜない |
| 読み込みDB | 初期採用数を1にする。固定側を指定した場合は固定側を優先する |
| 固定側の着手 | 本家と同様、確定局の更新対象にも含める |

初期登録も本家と同じ順序です。DBを読み込んだ後、開始前の参考手順の各局面を「その1手・1000」に置き換えます。固定側を選んだ場合も、開始前の参考手順は定跡DBへ登録します。

比較で見つかった「逆順削除の停止後に負け側を加算しない」「世代で結果を除外する」「固定側の着手を更新から外す」という違いは公開版で修正しました。`tests/test_app.py` は本家ファイルの定跡更新ループをASTからそのまま抽出し、異なる候補・同一局面の再出現・固定手・古い世代を含む入力で比較します。元スクリプト全体は起動しません。

次の点は実行・保存のための明示的な違いです。

- 共有定跡と棋譜をSQLiteの単一管理プロセスが確定し、途中局は勝敗や定跡更新へ加えません。
- 千日手は局面・持駒・手番の4回一致で扱い、開始前の参考手順を数えません。未着手の次の手を登録しません。連続王手による反則は通常の千日手と区別します。
- 入玉宣言、非合法手、通信障害を検査します。入玉宣言は管理側で27点法の条件を確認しますが、エンジンの入玉規則オプションは変更しません。
- エンジンへは画面指定のThreads・Hash・投了値だけを設定し、内蔵定跡やその他のオプションは変更しません。
- 総手数上限を設けます。千日手と手数上限の定跡更新上の扱いを選択でき、既定は先手負けです。公式結果は引分・未決着として区別します。
- 入出力はUTF-8、手数を除いたSFENを局面キーにします。
- 探索条件と並列数は設定可能です。初回の `isready` 以外に局ごとの初期化や乱数seed固定をしません。

比較は定跡更新の互換性の確認です。エンジン探索の非決定性まで同じ棋譜になることを保証するものではありません。
